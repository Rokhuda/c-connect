# C Connect — Work Readiness Programme Project

A simulated, production-shaped build for **30 candidates** on a work readiness programme:
**18 Software Engineers** and **12 Cloud Engineers**, organised into 10 squads.

The domain is modelled on the **Cassava Technologies** group of businesses — connectivity
(Liquid Intelligent Technologies), data centres (Africa Data Centres), fintech (Sasai),
renewable energy (Distributed Power Africa) and AI (Cassava AI) — so candidates work on
problems that look and feel like the real thing.

> **Note:** This is a training project. It is not affiliated with or endorsed by Cassava
> Technologies. Do not use real Cassava logos, customer data, credentials or internal APIs.
> All data is synthetic and generated by the seed scripts in this repo.

---

## What candidates build

**C Connect** is a single self-service portal where a business customer can:

| Capability | Owning squad | Real-world analogue |
|---|---|---|
| Sign up, sign in, manage org + roles | Squad 1 — Identity | Sasai ID / SSO |
| Check fibre coverage, order connectivity, track installs | Squad 2 — Connectivity | Liquid Intelligent Technologies |
| Request rack space, power draw, remote-hands tickets | Squad 3 — Colocation | Africa Data Centres |
| View invoices, pay, manage wallet + top-ups | Squad 4 — Payments | Sasai Fintech |
| Monitor solar/battery output at a site | Squad 5 — Energy | Distributed Power Africa |
| Ask a support copilot questions about their account | Squad 6 — AI Assistant | Cassava AI |

The **four cloud squads** build the platform: infrastructure as code, a Kubernetes
runtime, GitOps delivery, and observability with cost visibility.

Two things shape the whole programme:

**Everything is open source and self-hosted.** OpenTofu, Kubernetes, Argo CD, Keycloak,
PostgreSQL, MinIO, NATS, Harbor, OpenBao, Prometheus, Grafana, Loki, Tempo, OpenCost.
No proprietary managed services. Candidates run the real thing, so the knowledge
transfers to whatever a placement employer uses.

**Software squads do DevOps too.** Each one containerises its own service, owns its own
CI pipeline and Helm chart, builds its own dashboard, defines its own SLO, writes its
own runbook, and takes an on-call shift on game day. The cloud squads build golden
paths — they do not operate other people's services.

## Quick start (facilitator)

```bash
gh auth login                       # needs: repo, project, admin:org, workflow scopes
export GH_ORG="your-org"            # e.g. c-connect-wrp-2026
export GH_REPO="c-connect"

./scripts/00-bootstrap-repo.sh
./scripts/01-create-project-board.sh
./scripts/02-seed-issues.sh
```

Then read `docs/FACILITATOR-SETUP-GUIDE.md` for the org, permissions and onboarding steps.

## Quick start (candidate)

1. Accept the org invite and find your squad in `docs/TEAM-STRUCTURE.md`.
2. Open the **C Connect Delivery** project board, filter to your squad label.
3. Pull the top ticket from **Ready**, assign yourself, move it to **In Progress**.
4. Read `docs/WAYS-OF-WORKING.md` before your first pull request, and
   `docs/COMPETENCY-FRAMEWORK.md` before you ask your first question.

Sprints are **10 working days**. See `docs/SPRINT-RHYTHM.md` for what happens on each one.
